# 🏫 학급 규모(20~30명) 주식 시뮬레이션과 실제 주식 시장 시스템 비교 분석 및 개선안

> 본 문서는 실제 주식 시장의 거대한 금융 하부 구조와 stockGame 프로젝트의 설계 사양을 다각도로 비교 분석하여, **비슷한 점(Similarities), 차이점(Differences), 그리고 학급 환경에 최적화된 기술적·기획적 개선점(Improvements)**을 체계적으로 도출한 분석 보고서입니다.

---

## 1. 실제 시스템과 stockGame 메커니즘의 비슷한 점 (Similarities)

stockGame은 소규모 프로젝트임에도 불구하고, 실제 주식 거래의 핵심 논리와 데이터 무결성 원칙을 충실히 구현하고 있습니다.

* **엄격한 매칭 엔진 규칙과 부분 체결**:
  * 실제 거래소의 가격우선·시간우선 원칙을 동일하게 적용.
  * 매수/매도 수량이 일치하지 않더라도 체결 가능 수량만큼 즉시 체결하고 잔량을 대기시키는 **'Split(분할) 기반 부분 체결 시스템'**을 통해 트랜잭션 무결성 확보.
* **실시간 시세 및 호가창 브로드캐스트**:
  * 실제 거래소의 FEP 및 멀티캐스트 시세 네트워크 방식을 웹 환경에 맞추어 **STOMP 프로토콜(WebSocket)**로 구현.
  * /topic/orders/{stockId}를 통한 실시간 호가창 브로드캐스트 및 /queue/notifications를 통한 개인 체결 즉각 알림 전송.
* **호가 규칙(Tick Size) 및 기준가 스케줄링**:
  * 코스피 시장과 동일한 가격대별 호가 단위 강제 검증 로직을 탑재하여 허수 호가 원천 차단.
  * 매일 자정 스프링 스케줄러(Spring Scheduler)를 통해 기준가(prev_price)를 자동 동기화하는 마감 배치 구조 보유.
* **금융 정책 통제 구조 (Admin/Teacher)**:
  * 금융위원회/거래소의 시장 관리 조치와 유사하게, 관리자 패널(Admin Panel)을 통한 **신규 주식 상장(IPO), 상장폐지, 시장 개장/휴장 원터치 토글** 기능 제공.

## 2. 실제 시스템과 stockGame 메커니즘의 차이점 (Differences)

* **T+2 결제 및 소액결제망 연계 vs 즉시(T+0) 원장 반영**:
  * **실제 시스템**: 체결(T) $\rightarrow$ 중앙청산소(CCP) 다자간 차감 $\rightarrow$ **T+2일** 예탁결제원 계좌 대체기재 및 한국은행 BOK-Wire를 통한 동시결제(DVP).
  * **stockGame**: 체결 즉시 DB 잔고에 반영되는 **실시간(T+0) 결제 구조**.
  * **학급 환경 평가**: 교육용 게임에서는 투자 피드백의 즉각성이 중요하므로, **T+0 즉시 결제 방식은 게임성과 몰입도 측면에서 최적의 타협**.
* **무한 유동성 시장 vs 극심한 호가 공백**:
  * **실제 시스템**: 수천만 명의 참여자로 인해 호가 스프레드가 극히 좁음.
  * **stockGame**: 20~30명 참여 환경에서는 매수-매도 희망가 간격이 벌어져 **거래가 장기간 체결되지 않는 '호가 공백(Market Freezing)'** 발생.
* **소수 세력에 의한 시세 조종 (어뷰징/자전거래)**:
  * **실제 시스템**: 대형주 대상 시세 조종이 어렵고 시장감시 시스템이 작동.
  * **stockGame**: 2~3명의 학생이 담합하여 비우량주를 1주씩 고가에 주고받으며 가격을 띄우는 **시세 조종 위험** 상존.

## 3. 학급 규모 맞춤형 핵심 개선 및 고도화 제안 (Improvements)

### ① 하이브리드 LP 봇(Smart Liquidity Provider Bot) 탑재 및 어뷰징 차단 (추천 ⭐)
* **작동 메커니즘**: 스프레드가 일정 기준(예: 5%) 이상 벌어지거나 호가창이 비었을 때, 시스템 계정(SYSTEM_LP)이 개입하여 호가 공급.
* **어뷰징 방지 필터 (거래량 가중 평균가 - VWAP)**:
  * 봇의 개입 기준가를 '직전 1건 체결가'가 아닌 **최근 N건의 이동평균(MA)** 또는 **거래량 가중 평균가(VWAP)**로 설정.
  * 소수 학생의 1주 자전거래로 봇의 기준가가 왜곡되는 현상을 차단.
* **스프레드 페널티(Spread Margin)**:
  * 봇의 매수 호가(예: 950원)와 매도 호가(예: 1,050원) 사이에 마진을 두어, 봇을 상대로 즉각 사고파는 단타 시 무조건 손실이 발생하도록 설계.

### ② 간이 변동성 완화장치 (Static VI) 도입
* **적용 방안**: 당일 시초가 대비 개별 종목 주가가 **±10% 이상 급등락** 시 즉시 실시간 체결을 멈추고 **2분간 '단일가(동시호가) 매매' 모드로 전환**.
* **교육 효과**: 시장 과열 시 냉각기를 주는 실제 한국거래소의 시장 안정화 메커니즘을 자연스럽게 체험.

### ③ UI 상의 '결제 지연(T+2)' 교육용 연출 (Conceptual Lagging)
* **적용 방안**: 백엔드는 T+0 즉시 결제를 유지하되, 프론트엔드 UI 대시보드에 매도 대금을 **"T+2 결제 대기 자금 (출금 제한 포인트)"**으로 표시. 이틀 뒤 결제 시점이 지나야 쿠폰 상점 구매가 가능하도록 연출.
* **교육 효과**: *"주식을 팔았는데 왜 즉시 출금이 안 되나요?"*라는 실제 증권 시장의 결제 주기 개념을 직관적으로 학습.

### ④ 소수단위 주식거래 (Fractional Shares) 도입
* **적용 방안**: 보유 수량 데이터 타입을 실수형(Double/BigDecimal)으로 허용하여 **'0.1주' 단위 매매 지원**.
* **교육 효과**: 초기 포인트가 적은 학생들도 고가 우량주를 분산 매수하여 포트폴리오 다변화 전략을 실습 가능.

## 4. 결론 요약

stockGame은 실시간 접속매매의 뼈대를 탄탄히 갖추고 있으며, 여기에 **"VWAP 기반 어뷰징 차단 하이브리드 LP 봇"**과 **"UI 단계에서의 T+2 출금 대기 연출"**을 접목하면 학급 환경의 한계를 극복하면서 최고 수준의 교육용 모의투자 플랫폼으로 완성될 수 있습니다.
